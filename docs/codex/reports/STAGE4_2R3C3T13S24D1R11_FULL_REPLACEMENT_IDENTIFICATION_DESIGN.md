# Stage4.2R3c3T13S24D1R11 full-replacement identification design

## Frozen status and purpose

This design is frozen after complete D1R10 raw forensics and before D1R11
implementation, package construction, run-directory creation, Ray startup,
or any new TSC trajectory.

D1R11 asks whether the D1R9-selected 24-row schedule can support the original
S24 causal recursive-transition identification contract on the complete
20-whole-pair/40-context partition. It is a fresh experiment identity. Every
baseline and every sequential response is generated by a fresh controller and
fresh TSC process; no S24, D1R2, D1R6, D1R8, or D1R10 trajectory is reused as
a fit, calibration, or holdout observation.

D1R11 is identification only. It does not implement or run MPC, create expert
data, validate long hold, authorize BC/DAgger/RL, or change the formal timing
contract.

the D1R9 requested matrix. It may use only current/past visible R/Z/Ip,
current/past 14-coil currents, target, causal task-start actuator values, and
the fixed causal task clock. It may not use pair/history/partition labels,
source or current-run outcomes, source actions/currents, hidden wire/vessel
currents, post-action same-step telemetry, or any future action/measurement.

No D1R11 outcome may be used to alter this model search or acceptance rule:

Model selection order is frozen as formal-verdict mismatch count, maximum
recursive scaled error, mean-squared recursive scaled error, feature order,

source results/actions, matched baseline values, coil/wire/hidden currents,
actual future coordinates, post-effect current, and future values are
forbidden predictor fields exactly as in S24.

## Fail-closed phase opening

The phases must execute in this order:

```text
offline source/spec/snapshot audit, zero TSC
→ 24 training baselines
→ 576 training sequences
→ freeze and hash the training model
→ 8 calibration baselines
→ 192 calibration sequences
→ freeze and hash the calibrated tube
→ 8 fresh holdout baselines
→ 192 fresh holdout sequences
→ independent full-raw recomputation
```

No calibration raw may exist before the training artifact is accepted and
hash-frozen. No holdout raw may exist before the calibrated tube is accepted
and hash-frozen. A phase failure prevents all later outcomes from opening.
Resume may schedule only missing or byte-invalid raw within an already
authorized unchanged phase; it may not rerun valid successes or structured
safe stops.

Formal-verdict reproduction is a model acceptance gate. Probe-trajectory
tracking percentages are reported diagnostically and are not by themselves a
controller or MPC result. No horizon extension or deadline reinterpretation
is allowed.

## Required validation and independent acceptance

Before real TSC, D1R11 must pass local compile, strict JSON parse, focused and
complete tests, source-fingerprint and resume-compatibility tests, import
closure, manifest/checksum verification, and an empty-directory direct-copy
deployment simulation. Server staging and installed validation must use only
the existing virtualenv and pass package hashes, shell syntax, imports,
compile, focused/complete tests, exact-path guards, and a zero-TSC offline
audit proving 1,000/1,000 specs and zero raw/plant advances.

After every opened real phase, an independent server-side reader must
recompute strict raw inventory, identity, authentic restart, causality,
calibration, schedule/action/current gates, forbidden-use counts, runtime and
solver failures, phase ordering, saved model/tube hashes, and all model/formal
statistics. Large raw remains on the server; only compact hash-bound evidence
may be downloaded.

Ray campaign capacity is fixed at 128 and each task timeout at 180 seconds.
No worker-count increase may create a new semantic identity or weaken a gate.

## Authorization boundary

A D1R11 pass authorizes only prospective design of a separate zero-new-TSC
robust finite-horizon feasibility and controller stage using the frozen model
and calibrated tube. It does not authorize real MPC execution, expert-dataset
creation, BC, DAgger, or RL.

Before RL, the project must still demonstrate a reliable constrained MPC
expert under authentic restart/controller-state restart, hidden-history and
different-initial-state variation, preregistered unseen targets, continuous
delay/gain/slew and plant/Jacobian error, measurement noise/observer
uncertainty, disturbance recovery, and independent long hold.
