# Stage4.2R3 preregistered hidden-history and initial-state design

Preregistered: 2026-07-30 Asia/Shanghai

Status: fixed before any Stage4.2R3 TSC state-generation or control result.

## 1. Scientific question

Stage4.2R3 asks whether the frozen causal MPC expert can control authentic TSC
states that:

1. have closely matched controller-visible state but materially different
   full vessel/wire-current state; and
2. differ from the frozen R17 task initial state.

R3 must not edit `sprsina`, coil-current files, wire-current files, or hidden
state. Every initial state must be generated by real TSC actions, exported by
the existing snapshot interface, hash-verified, and restarted in a fresh TSC
process.

The immutable arrival and hold contract remains:

```text
slew 1.0/1.1: arrive by 250 ms, evaluate through 350 ms
slew 0.9:     arrive by 270 ms, evaluate through 370 ms
```

## 2. Why the existing R1/R2 bank cannot certify R3

The R1/R2 matrix contains one trajectory and one 200 ms snapshot for each
`(target, delay, slew)` key. A matched-visible/different-hidden comparison
must hold the future target and actuator semantics fixed. Pairing different
R1 keys would confound hidden history with target, delay, or slew; pairing a
case with itself has no hidden separation.

The existing bank will be audited in place on the server, but cross-key
nearest neighbours are exploratory diagnostics only. They cannot pass the R3
pair gate.

Therefore, if the audit confirms one history per key, R3 requires an
authenticated state-generation phase before the control phase.

## 3. Authentic hidden-history generation

All pair members start from the same frozen TSC start folder and use the same
environment configuration. A deterministic full-coil direction is chosen
from the orthogonal complement of the frozen three-mode controller basis.
This reduces first-order plasma-control coupling without claiming a perfect
physical nullspace.

For a unit direction `q`, two real TSC histories are generated:

```text
member plus-first:   +a*q, -a*q, then zero delta-current actions
member minus-first:  -a*q, +a*q, then zero delta-current actions
```

The two-step command has exactly zero requested net coil-current increment.
The reversed ordering is intended to leave different passive vessel-current
history after the commanded coil currents have returned. No snapshot content
is modified.

Fixed candidate grid:

```text
nullspace direction indices: 0, 1, 2
amplitude fractions:          0.05, 0.10, 0.20
zero-action settle steps:     4, 8, 12
history orders:               plus-first, minus-first
candidate pairs:              27
state-generation rollouts:    54
```

Every rollout requests an authentic snapshot after
`2 + settle_steps` TSC transitions. Action magnitude may never exceed 0.20
normalised units. A TSC abnormal exit, incomplete trajectory, non-finite
telemetry, missing payload, hash mismatch, or snapshot/wire mismatch makes
that member invalid.

## 4. Fixed pair-validity thresholds

Pair validity is evaluated before and without reading any subsequent control
result.

Current visible-state matching:

```text
absolute R difference                         <= 0.0005 m
absolute Z difference                         <= 0.0005 m
absolute Ip difference                        <= 2,000 A
absolute backward-difference vR difference    <= 0.02 m/s
absolute backward-difference vZ difference    <= 0.02 m/s
maximum 14-coil current difference            <= 2,000 A
RMS 14-coil current difference                <= 500 A
maximum endpoint action difference            <= 1e-12 normalised
same TSC transition count and snapshot clock  required
```

The R2 controller uses causal R/Z/Ip history and physical coil state. Full
wire current and the aggregate vessel-current telemetry derived from it are
audit-only hidden variables; they are not included in controller input or in
the visible matching score.

Material hidden-state separation:

```text
wire-vector length                                 exactly 48
maximum absolute full-wire difference              >= 1,000 A
relative RMS full-wire difference                  >= 0.05

relative RMS = RMS(h_plus - h_minus)
               / max(1 A, 0.5*(RMS(h_plus)+RMS(h_minus)))
```

These thresholds will not be weakened after state-generation results are
seen.

## 5. Pair selection without outcome leakage

All 27 candidate pairs are evaluated against the fixed state-only gate.

For each nullspace direction, select at most one accepted pair:

1. largest relative RMS hidden-wire separation;
2. then smallest maximum of the normalised visible matching ratios;
3. then lower amplitude;
4. then longer settle;
5. then lexical pair ID.

Selection reads no control trajectory, formal metric, or verdict. All
selected pairs proceed to the complete control matrix. A pair may not be
removed because its later control result is unfavourable.

At least two selected pairs are required for the primary hidden-history
campaign. Fewer than two is a state-generation/design failure, not a
controller failure. No formal control phase may run in that case.

## 6. Different-initial-state gate

For each selected pair, compare its visible centroid with the frozen R17
initial state. It counts as a different initial state only if at least one of
the following is true:

```text
absolute R centroid difference       >= 0.0005 m
absolute Z centroid difference       >= 0.0005 m
absolute Ip centroid difference      >= 2,000 A
RMS 14-coil centroid difference      >= 500 A
```

At least two selected pair centroids must satisfy this gate. Hidden-state
difference alone does not certify visibly different initial-state coverage.

## 7. Fixed control matrix

For every selected pair, both history members are restarted in fresh TSC
processes. The controller starts causally from the new task initial state with
empty future data, zero integral, no fabricated observer state, and the
frozen trusted actuator calibration.

Fixed matrix:

```text
targets:                nominal, RZ_p10_m10
future actuator cases:  (delay 0, slew 1.0), (delay 2, slew 0.9)
history members:        plus-first, minus-first
selected pairs:         2 or 3
expected rollouts:      16 or 24
```

The future target and actuator case are identical within each history pair.
All actions must be computed online from causal controller inputs. Full wire
telemetry is recorded only after the action has been chosen.

## 8. Primary gates and classification

The state-generation phase reports:

- runtime/environment errors;
- snapshot corruption;
- invalid visible match;
- insufficient hidden separation;
- insufficient different-initial-state separation;
- accepted and selected pairs.

The control phase separately reports:

- fresh controller and fresh TSC process;
- causal trace and absence of future-action/measurement use;
- environment/runtime success;
- formal-contract result for every member;
- within-pair action and trajectory divergence as diagnostics;
- observer/history-identification limitation;
- real closed-loop control failure.

Primary R3 pass requires:

```text
selected pairs                              >= 2
selected different-initial-state centroids  >= 2
all planned control raw present and valid
future action/measurement use                0
fresh controller/TSC                         100%
formal contract                              100%
```

Exact equality between the two hidden-history members is not required and is
not expected. A finite R3 pass remains bounded to the selected authentic
state pairs and the two fixed future actuator cases.

## 9. Safety and stopping

- A failed or abnormal TSC process stops that rollout.
- No broad process kill or `/tmp` cleanup is permitted.
- Only exact stage PIDs and stage-owned temporary directories may be stopped
  or removed.
- State generation stops before control if fewer than two valid pairs exist.
- Any code change that alters the candidate grid, pair thresholds, controller
  action semantics, target matrix, actuator matrix, or formal gate requires a
  new run identity.

## 10. Evidence handling

Raw JSON.GZ and snapshot payloads remain on the server. A read-only server
postprocessor must parse and hash every raw/snapshot input and independently
recompute pair validity and formal metrics. Only compact JSON/CSV,
inventories, hashes, and logs are downloaded.

BC, DAgger, and residual RL remain prohibited.
